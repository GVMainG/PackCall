# Структура проекта

Для MVP рекомендуется разделить систему на три проекта. API и фоновый обработчик на этом этапе работают в одном приложении. Такое разделение отделяет бизнес-правила от способов доставки и хранения данных, не создавая лишних проектов.

## PackCall.Core

Доменная модель, бизнес-правила и сценарии приложения.

Проект должен содержать:

- сущности кампании, получателя и доставки;
- статусы и допустимые переходы между ними;
- команды и обработчики создания и запуска кампании;
- сценарий обработки одной доставки;
- проверку завершения кампании;
- DTO и интерфейсы репозиториев, часов, отправителей сообщений, журнала смены статусов, метрик и других внешних сервисов;
- доменные исключения и проверки инвариантов.

Проект не должен зависеть от Entity Framework, PostgreSQL, ASP.NET Core и конкретных каналов отправки.

## PackCall.Infrastructure

Реализация технических зависимостей приложения.

Проект должен содержать:

- `DbContext`, конфигурации Entity Framework и миграции;
- работу с PostgreSQL;
- реализации интерфейсов из `PackCall.Core`;
- атомарный захват доставок, включая сохранение идентификатора воркера и срока закрепления;
- реализацию mock-email и в будущем другие каналы доставки;
- хранение журнала смены статусов и публикацию метрик;
- регистрацию инфраструктурных зависимостей в DI.

Проект может зависеть от `PackCall.Core`.

## PackCall.Api

HTTP-интерфейс системы и фоновая обработка доставок.

Проект должен содержать:

- контроллеры или minimal API endpoints;
- HTTP-модели запросов и ответов;
- преобразование HTTP-запросов в команды приложения;
- настройку авторизации, OpenAPI, middleware и обработку ошибок;
- регистрацию зависимостей приложения и инфраструктуры;
- фоновый `BackgroundService` для обработки доставок и назначение идентификатора воркера;
- настройку предоставления метрик.

Проект не должен содержать бизнес-логику кампаний и напрямую работать с `DbContext` в контроллерах или фоновом обработчике.

## Зависимости проектов

```text
PackCall.Core
    ↑
PackCall.Infrastructure
    ↑
PackCall.Api
```

`PackCall.Api` является точкой сборки приложения и может ссылаться на `PackCall.Infrastructure` для регистрации зависимостей. Бизнес-сценарии должны находиться в `PackCall.Core`.

Отдельные проекты для кампаний, доставок, получателей или каналов связи на этапе MVP создавать не нужно. Их следует организовать в виде модулей и папок внутри перечисленных проектов.
