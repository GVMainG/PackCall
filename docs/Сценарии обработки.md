# Сценарий создания, запуска и завершения кампании

## Создание кампании

1. Пользователь отправляет в API запрос на создание кампании со следующими параметрами:
    - название;
    - текст сообщения.
2. Система создаёт кампанию и заполняет её поля:
    - поле «Статус» получает значение «Черновик»;
    - поля «Дата создания» и «Дата изменения» получают текущие дату и время;
    - поля «Дата начала» и «Дата завершения» остаются пустыми.
3. Система определяет список получателей и создаёт отдельную доставку для каждого из них. Новая доставка получает статус «Ожидает».
4. Пока кампания находится в статусе «Черновик», пользователь может редактировать её через API. После запуска редактирование кампании запрещено.

## Запуск кампании

1. Пользователь отправляет в API запрос на запуск кампании.
2. Система переводит кампанию из статуса «Черновик» в статус «Запущена» и записывает текущие дату и время в поля «Дата начала» и «Дата изменения».
3. Фоновые обработчики начинают обрабатывать доставки со статусом «Ожидает».
4. Повторный запрос на запуск уже запущенной кампании не изменяет её состояние и не создаёт новые доставки.
5. Завершённую кампанию нельзя запустить повторно.

## Завершение кампании

1. После обработки каждой доставки система проверяет состояния остальных доставок кампании.
2. Когда все доставки получают конечный статус «Доставлена» или «Ошибка», система:
    - переводит кампанию в статус «Завершена»;
    - записывает текущие дату и время в поля «Дата завершения» и «Дата изменения».
3. Наличие доставок со статусом «Ошибка» не препятствует завершению кампании. Количество успешных и неуспешных доставок отображается отдельно.

# Жизненный цикл доставки

## Создание доставки

1. Система создаёт доставку для одного получателя кампании.
2. Доставка получает статус «Ожидает».
3. Поля «Дата создания» и «Дата изменения» получают текущие дату и время, а поле «Дата завершения» остаётся пустым.
4. Адрес получателя сохраняется в доставке как снимок контактных данных на момент её создания.

## Обработка доставки

1. Фоновый обработчик атомарно забирает доставку со статусом «Ожидает».
2. Доставка получает статус «Отправляется», а поле «Дата изменения» — текущие дату и время.
3. Обработчик передаёт сообщение мок-оператору:
    - если мок-оператор принял сообщение, доставка получает статус «Доставлена»;
    - если мок-оператор вернул ошибку, доставка получает статус «Ошибка».
4. При переходе в статус «Доставлена» или «Ошибка» поля «Дата завершения» и «Дата изменения» получают текущие дату и время.

## Прерывание обработки

1. Доставка в статусе «Отправляется» закрепляется за обработчиком на ограниченное время.
2. Если обработчик завершил работу до сохранения результата, после истечения срока закрепления доставка снова получает статус «Ожидает».
3. Другой обработчик может повторно забрать такую доставку.
4. Идентификатор доставки передаётся мок-оператору как ключ идемпотентности. Повторная передача доставки с тем же идентификатором не должна приводить к повторной отправке сообщения.

## Допустимые переходы статусов доставки

- `Ожидает` → `Отправляется`;
- `Отправляется` → `Доставлена`;
- `Отправляется` → `Ошибка`;
- `Отправляется` → `Ожидает`, если обработка была прервана и истёк срок закрепления доставки.

Статусы «Доставлена» и «Ошибка» являются конечными. В рамках MVP повторная отправка доставки, завершившейся явной ошибкой, не выполняется.

# Критерии завершения кампании

Кампания считается завершённой, если выполняются все следующие условия:

- для каждого получателя создана и обработана доставка;
- ни одна доставка не находится в статусе «Ожидает» или «Отправляется»;
- каждая доставка находится в конечном статусе «Доставлена» или «Ошибка».
