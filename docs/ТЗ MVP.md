# О чем проект и зачем ог создается

Проект PackCall создается в первую очерь с целью получения опыта разработки высконагруженных систем с нуля.

# Основные сущности

[[Модель данных MVP.md|Модель данных]]

## Кампания

Одна массовая рассылка с сообщением и выбранной аудиторией.

## Получатель

Человек или система, которым предназначено сообщение.

## Доставка

Работа по отправке сообщения одному получателю и её текущий результат.

# Использование системы пользователем

1. Пользователь создаёт кампанию: указывает текст сообщения через API.
2. Система определяет статичных получателей, выбирается канал доставки - email и создаёт для них доставки.
3. Пользователь запускает кампанию.
4. Система отправляет сообщения получателям в фоновом режиме.
5. Пользователь в любой момент смотрит состояние кампании: сколько сообщений ожидают отправки, сколько отправлено и сколько завершилось ошибкой.

# Бизнес-процесс работы системы

1. API принимает команду создать и запустить кампанию.
2. Система использует заранее заданный статичный список получателей.
3. Для каждого получателя система сохраняет отдельную доставку со статусом ожидания.
4. Фоновые обработчики забирают ожидающие доставки и передают их каналу отправки.
5. После каждой попытки система сохраняет результат доставки: успех или ошибку.
6. Когда все доставки кампании получили конечный результат, кампания считается завершённой.

## Domain-agnostic архитектура

После MVP отделить движок массовой доставки от конкретной предметной области. Подключаемый доменный модуль должен предоставлять движку список получателей и данные для сообщения, а PackCall — отвечать за общий процесс массовой доставки и хранение её статусов.

В MVP эта архитектура не реализуется: система работает с заранее заданным статичным списком получателей и не обязана поддерживать подключение разных доменных модулей.
