# Запрос захвата под нагрузкой и индекс очереди

Проверка после [Story 2.6](300k-schema-gate.md) на продукте `b935a11d42e1971ffbe08be17dc77d95b5d3f17a`. Стенд использует 300 000 синтетических доставок, два Worker и HTTP-оператор без симуляции ошибок. Базы принадлежат отдельным локальным сеансам.

## План запроса

В отдельном диагностическом сеансе `cd8e3b6f-28e7-4a03-a9e0-15dcb47f18fe` включили `auto_explain` на PostgreSQL. Сохранили планы реальных вызовов Worker, включая блокировку кандидатов, вычисление срока аренды, `UPDATE` и возврат результата. Выборка 10% вызовов, минимальная длительность 1 мс, `ANALYZE` и `BUFFERS` включены, замер времени каждого узла выключен. Диагностический сеанс исключён из сравнения throughput.

В наиболее позднем из сохранённых планов с максимальным числом отброшенных строк захват на 10 строк сканировал `pk_deliveries_id`, отбросил 295 000 строк и получил 295 805 попаданий в кеш блоков. Весь запрос занял 130,13 мс. PostgreSQL учитывал `delivery_status`, канал и адрес как фильтры поверх сканирования по ID. Сохранили 791 план без текста запросов в `artifacts/story-2-6/live-plan/capture-plans.jsonl`, SHA-256 `5c760b6eae630e5706306421081efde7036ba45fb4941ef7e4e36d0d8a0c5c0e`. Диагностическая кампания завершилась с 300 000 уникальных `Sent`.

## Проверка индекса

```sql
CREATE INDEX ix_deliveries_status_id ON deliveries (delivery_status, id);
```

Первый столбец индекса ограничивает сканирование статусом `Waiting`, второй даёт требуемый порядок по ID. Индекс создаётся на каждой подготовленной тестовой БД до старта Worker и окна замера. Запрос захвата, проверка канала и адреса, `SKIP LOCKED`, срок аренды и журнал сохраняются. Сбор планов в этой серии выключен.

## Проверки и решение

- Драйвер `24ede077f625283cba17ed6d0c3e6e813b3cb463`, отпечаток исходников `e0d8ed4c3b49e3489f30e3c0ef637cf065ad9f63c8fbc51bf1a1b1533fd64d68`. Использованы те же образы продукта, PostgreSQL и оператора, что и в Story 2.6. В каждой базе подтверждён DDL через `pg_get_indexdef`. Квитанции индекса, фоновые выборки и локальный сценарий `diagnose_live.py` лежат под `artifacts/story-2-6/`.
- Пересчёт по исходным файлам подтвердил все шесть сеансов. Каждый дал 300 000 уникальных `Sent`, статус `Completed`, ноль `Failed`, вклад обоих Worker и сверку журнала. Стенды очищены.
- Самый медленный сеанс с индексом показал 851,85 доставки/с. Самый быстрый сеанс Story 2.6 без индекса показал 596,26 доставки/с по нижним оценкам. Измерения на разных сериях показывают устойчивое направление эффекта. Точный размер выигрыша зависит от условий стенда.
- Гейт `beta.3` остаётся закрытым при текущем допуске разброса. Индекс создавался только в тестовых базах. Для выпуска остаётся оформить его в миграции и провести стабильную серию на выделенном стенде.
