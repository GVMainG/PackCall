# Story 2.6 — проверка миграции индекса захвата

Кандидат `c1854caeda1905b43127e6846e84e3c988e55724` добавляет
`20261117140341_DeliveryCaptureIndex`. Запрос захвата и существующие индексы
сохранены. См. [замеры экспериментального индекса](capture-index-experiment.md).

EF Core 10.0.4 сгенерировал три SQL-скрипта: от пустой базы до новой миграции,
откат до `ContactsChannels` и повторное применение. На отдельном PostgreSQL 18.6
с точным ID из beta.2 `pg_get_indexdef` подтвердил B-tree
`(delivery_status, id)` после применения и повтора; после отката индекс
отсутствовал. Временный контейнер и его том удалены. Драйвер замеров прошёл
71 тест и 69 подтестов; историческая медиана пересчитана из закреплённых
артефактов: 644,9564565903767 доставки/с.

Гейт не запускался: исходный локальный образ HTTP-оператора
`sha256:8df0464b77ae6b7e27776ad480ef25406111ba167ba29ce0d62c34f0b56361d4`
недоступен. Повторная сборка из исходников beta.2 дала другой ID
`sha256:4cd60e10a57d4fe23a74b6f09bb602264e306d608e09d5c30cf119643b977455`.
Подстановка другого образа к историческим замерам не допускается.
Для продолжения нужен исходный образ либо новый baseline beta.2 и замер
кандидата с одним и тем же заранее сохранённым образом. Порог и допуск
разброса неизменны: не более 10% потери и не более 5% разброса.
