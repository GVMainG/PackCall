# Baseline на 300 000 доставок для v0.5.0-beta.2

Коммит продукта `113d228b6803f9a2b2c98a007925764dc3f5b7b2`. Профиль `windows-http-300k` использует два независимых Worker на одной БД, тестовый HTTP email-оператор и `simulate_errors=false`. Подготовка кампании, остановка и выгрузка итоговых сверок проходят вне окна обработки.

## Протокол

- Чистая серия `off/on`, `on/off`, `off/on`. Для каждого сеанса используется новая БД и один и тот же набор образов из тега. В обоих режимах driver опрашивает БД по одинаковому протоколу. `off` отключает штатный сбор API, Worker и внешних диагностических выборок.
- Throughput равен `300000 / Δ`, где `Δ` измеряется монотонными часами driver от начала запроса запуска до ответа первого опроса с 300 000 `Sent` и `Completed`. Граница предыдущего незавершённого опроса задаёт диапазон неопределённости. Порог потери throughput применяется к медиане парных `100 × (1 − on/off)`. Разброс `off` считается как `(max − min) / median`. Выше 5% требуется повтор серии.
- Пары `off/on`, `on/off` с одинаковым зондом на Worker оценивают добавочный вклад штатного сбора в `processing.total`. Зонд включает `PerformanceMetrics.Enabled` в обоих плечах. p95 считается по всем значениям обоих Worker в одном сеансе методом nearest rank. Лимит роста 10% применяется к каждой паре.
- Пересечение порога с диапазоном неопределённости требует повторного замера. Отсутствие доказательства или превышение бюджета оставляет гейт `beta.3` закрытым. Для подтверждённого превышения предусмотрены успешный повтор или решение владельца в ADR.

## Среда

Хост Windows 11 Pro, сборка 28000, AMD Ryzen 7 7700 (8 физических ядер, 16 логических), 33 346 736 128 байт видимой ОЗУ, план питания «Сбалансированная» со сном от сети `0` с. Docker Engine 29.8.2 и Compose 5.6.0, Linux x86_64 на WSL2, 16 vCPU и 22 435 524 608 байт ОЗУ Docker VM. Driver запущен на Python 3.13.3 через `uv`. Хостовый SDK `11.0.100-rc.2.26504.105`, продуктовые образы используют .NET 10 из Dockerfiles тега.

Перед серией 300k было доступно 10 468 495 360 байт ОЗУ хоста и 87 268 556 800 байт на диске. Начальная выборка загрузки хоста составила 1,28 логического ядра. У сервисов не задано отдельных лимитов CPU/RAM и привязки к ядрам. У каждого Worker четыре параллельные линии, batch 10, аренда 90 с, recovery 15 с, ожидание очереди 250 мс, пауза после ошибки 5 с. HTTP timeout 5 с, интервал телеметрии 10 с. Payload состоит из 64 байт синтетического текста, адреса из 29 байт. Очередь не пополняется.

Для лимита 128 MiB используется системный пик working set всего процесса Python с начала серии. В него входят и операции драйвера между сеансами. Средний CPU внешнего сборщика считается по времени его потока, включая проверку и запись данных. CPU дочерних `docker`, `psql` и PowerShell в этот счётчик не входит. Их работа проходит одновременно с доставками и отражается в сравнении throughput.
