# API действия MVP

## GET

| Маршрут | Входные данные | Успешный ответ |
| --- | --- | --- |
| `/api/campaigns` | `pageNumber`, `pageSize` | `200`: страница кампаний |
| `/api/campaigns/{id}` | GUID кампании | `200`: объект `campaign` и статистика `deliveries`: `total`, `waiting`, `inProgress`, `sent`, `failed` |
| `/api/campaigns/{id}/deliveries` | GUID кампании; `pageNumber`, `pageSize` | `200`: страница доставок кампании |
| `/api/deliveries/{id}` | GUID доставки | `200`: доставка |
| `/api/recipients` | `pageNumber`, `pageSize` | `200`: страница получателей |
| `/api/recipients/{id}` | GUID получателя | `200`: получатель |

## POST

| Маршрут | Тело запроса | Успешный ответ и поведение |
| --- | --- | --- |
| `/api/recipients` | `email` | `201` и `Location`: созданный получатель для будущих кампаний |
| `/api/campaigns` | `name`, `messageText` | `201` и `Location`: черновик кампании после создания доставок для аудитории из БД |
| `/api/campaigns/{id}/start` | Без тела | `200`: текущее состояние кампании после запуска |

### Создание кампании

Отсутствующие или `null` значения `name` и `messageText` при создании заменяются пустыми строками. Проверка непустых значений выполняется при запуске и редактировании. Название ограничено 255 символами в модели хранения; предварительной проверки этой длины в API на теге `mvp` нет.

Доставки создаются синхронно в рамках запроса пакетами по 500 получателей. Пока операция выполняется, кампания имеет статус `Forming`; после завершения — `Draft`, доставки — `Waiting`. Ответ `201` возвращается после формирования всей аудитории. При исключении или отмене сервис пытается удалить частичную кампанию и её доставки. Автоматического восстановления формирования после аварийного завершения процесса нет. Повторный запрос создания не идемпотентен и создаёт новую кампанию.

### Запуск кампании

Запуск требует непустых названия и текста сообщения. Повторный запуск `InProgress` возвращает кампанию без сброса статусов и без новых доставок. Запуск `Forming`, `Completed` или `Failed` запрещён и даёт `409`; отсутствие кампании — `404`.

## PATCH

| Маршрут | Тело запроса | Успешный ответ и поведение |
| --- | --- | --- |
| `/api/campaigns/{id}` | `name` и (или) `messageText` | `200`: изменённая кампания; разрешено только в статусе `Draft` |

Хотя бы одно поле должно иметь значение, отличное от `null`. Пропущенное поле или `null` сохраняет прежнее значение. После подстановки оба итоговых значения должны быть непустыми: иначе `400`. Редактирование кампании в другом статусе даёт `409`, отсутствие кампании — `404`.

## DELETE

| Маршрут | Входные данные | Успешный ответ и поведение |
| --- | --- | --- |
| `/api/campaigns/{id}` | GUID кампании | `204`, без тела: кампания и связанные доставки удалены |

На теге `mvp` удаление запрещено только для `InProgress` (`409`). Это означает, что проверка сервиса допускает также `Forming` и `Failed`, а не только `Draft` и `Completed`. Отсутствие кампании даёт `404`. Журнал смены статусов не удаляется каскадно.

## Ошибки и вспомогательные маршруты

Обработчик исключений возвращает `ProblemDetails`: `400` для ошибок аргументов, `404` для ненайденных ресурсов, `409` для доменных ошибок и недоступных операций. Ошибки хранилища, не обработанные специально, не имеют обещанного кода `400` или `409`.

OpenAPI `/openapi/v1.json` и Swagger UI `/swagger` подключены только в окружении `Development`. API изменения и удаления получателя, чтения журнала, повторной отправки конечной доставки и выбора канала в MVP отсутствуют.

Источники на теге `mvp`: `src/PackCall.Api/Controllers/`, `Models/`, `Middleware/ApiExceptionHandler.cs`, `Program.cs`, а также `src/PackCall.Core/Services/CampaignService.cs`.
