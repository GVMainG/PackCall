Срез реализации: тег `mvp`, коммит `f5dc35787b388466ae687493a5437f5f0c6e44a9` от 22.10.2026. Документ сохраняет целевые требования и отделяет их от фактических возможностей этого среза. Наличие реализации и тестов не означает прохождение нагрузочного прогона; в рамках актуализации прогон не выполнялся.

Связанные документы: [ТЗ MVP](ТЗ%20MVP.md), [сценарии обработки](Сценарии%20обработки.md), [API действия](API%20действия.md), [модель данных](Модель%20данных%20MVP.md).

# Границы MVP

- Единственный канал — mock-email, без реальной отправки писем.
- Аудитория хранится в PostgreSQL; её можно подготовить заранее или пополнять через API для будущих кампаний. Во время формирования кампании состав аудитории следует сохранять неизменным.
- Статус `Sent` означает подтверждение приёма сообщения оператором. Доставка адресату не проверяется.
- Проверки требуют стенда с PostgreSQL и mock-оператором. Параметры стенда и генерации нагрузки фиксируются в отчёте.
- Гарантии внешнего эффекта для реальных операторов требуют отдельного соглашения об идемпотентности.

# Целевая нагрузка

| Показатель | Требование | Обоснование |
| --- | --- | --- |
| Размер кампании | До 100 000 доставок | Проверка пакетной записи, индексов, пагинации и массового обновления статусов |
| Активные кампании | До 3; всего до 300 000 незавершённых доставок | Конкуренция воркеров, блокировки и завершение независимых кампаний |
| Производительность | Не менее 100 доставок/с суммарно по всем воркерам, пока есть «Ожидает» | 6 000 переходов статуса в минуту достаточно для длительного прогона |
| Завершение набора | 300 000 доставок не более чем за 60 минут | Расчётно 50 минут при 100 доставках/с и 10 минут запаса |
| Создание кампании | 100 000 доставок не более чем за 5 минут | Не менее 333 созданий доставок в секунду |
| Управляющие API | `GET`, запуск и повторный запуск: p95 не более 500 мс | Фоновая обработка не ухудшает пользовательские операции |
| Восстановление после падения воркера | Доставка возвращается из «Отправляется» в «Ожидает» не более чем за 2 минуты | Ограничение времени зависания доставки |

Производительность измеряется от появления доставок в статусе «Ожидает» до перехода последней доставки в конечный статус. Время преднамеренных остановок, недоступности PostgreSQL и искусственной задержки mock-оператора из измерения исключается.

# Гарантии обработки: требование и реализация

| Требование | Что реализовано на теге `mvp` | Ограничение проверки |
| --- | --- | --- |
| Ровно одна доставка для получателя кампании | Формирование пакетами по 500 и уникальный индекс кампания–получатель | Нет общего снимка аудитории и одной транзакции на всё формирование; при аварии возможна частичная кампания `Forming` |
| Повторный запуск безопасен | Уже запущенная кампания не меняется, новые доставки не создаются | Повторное создание кампании — другая операция, она не идемпотентна |
| Атомарный захват ожидающих доставок одним воркером | SQL с `FOR UPDATE SKIP LOCKED`, обновлением статуса и возвратом захваченного набора; выбираются только запущенные кампании | Защищает захват `Waiting`; сохранение результата не проверяет актуального владельца закрепления |
| Возврат после истечения закрепления | Отдельный цикл восстановления; по умолчанию срок 90 с и интервал 15 с | Требует работающего приложения и доступной БД; предел 2 минуты не подтверждён прогоном |
| Конечные `Sent` и `Failed` не отправляются повторно | Захват выбирает только `Waiting`, явная ошибка оператора сохраняется как `Failed` | Прерванный вызов без сохранённого результата может быть повторён |
| Завершение после всех конечных результатов | После обработки проверяется отсутствие `Waiting` и `InProgress` | Нет отдельного обхода: пустая кампания и сбой перед проверкой завершения могут оставить `InProgress` |
| Не более одной фактической отправки при повторе | `DeliveryId` передаётся в запросе оператора | Требование не реализовано: mock не хранит результат по идентификатору и не выполняет дедупликацию; реальной отправки в нём нет |
| Полный журнал переходов | Записываются захват, результат и возврат закрепления | Нет общей транзакции статуса и журнала; создание доставки не журналируется, при возврате прежний воркер уже очищен |

Система на этом срезе не заявляет `exactly once` или отсутствие повторного внешнего эффекта. После сбоя между вызовом оператора и сохранением результата повторный вызов возможен. Требование отсутствия дублей нельзя считать выполненным только потому, что mock не отправляет настоящие письма.

# Параметры обработки

| Параметр | Значение по умолчанию |
| --- | --- |
| Параллельные циклы обработки | 4 |
| Максимум доставок в захватываемом пакете одного цикла | 10 |
| Срок закрепления всего пакета | 90 секунд |
| Интервал проверки просроченных закреплений | 15 секунд |
| Ожидание при отсутствии работы | 250 мс |
| Задержка после ошибки цикла | 5 секунд |
| Задержка ответа mock-email | 10 мс |

Внутри пакета доставки обрабатываются последовательно; срок закрепления включает ожидание и не продлевается. Валидация настроек допускает от 1 до 64 параллельных циклов, положительный размер пакета, срок не меньше 10 секунд и сумму срока с интервалом восстановления не больше 2 минут. Это ограничение настроек, а не доказательство фактического времени восстановления при сбоях.

# Наблюдаемость и признаки корректности

Доступны чтение кампании со счётчиками статусов, страницы доставок, журнал `delivery_status_journal` в PostgreSQL и логи Serilog. У записи журнала есть идентификаторы кампании и доставки, прежний и новый статус, время события, необязательные воркер и результат оператора.

Сбор метрик отключён: зарегистрирован `NoOpDeliveryMetrics`, `MetricsController` помечен `NonController`, маршрут `/metrics` недоступен. Нагрузочный отчёт нельзя строить на предположении о работающем Prometheus endpoint.

Для измерения нужны внешние замеры времени API, периодическое чтение состояний и анализ БД/логов. Скрипт `scripts/load-test/seed_100000_recipients.sql` подготавливает аудиторию, но сам не выполняет прогон и не доказывает достижение целей.

# Проверочные сценарии

Ожидаемые результаты ниже — критерии проверки. Они не являются отчётом о том, что сценарии уже пройдены.

| Сценарий | Условия | Целевой результат и состояние реализации |
| --- | --- | --- |
| Номинальная нагрузка | Три кампании по 100 000 доставок; mock отвечает успехом | Не менее 100 доставок/с, полный набор за 60 минут, все доставки в `Sent`; требует измерения |
| Создание большой кампании | Заранее подготовить 100 000 получателей | Формирование за 5 минут, 100 000 уникальных доставок, итоговая кампания `Draft`; требует измерения |
| Конкурентный захват | Несколько воркеров захватывают один набор | До истечения закрепления одна ожидающая доставка не захватывается одновременно; отдельно проверить истечение срока и поздний результат прежнего воркера |
| Повторный запуск | Запустить кампанию дважды в `InProgress` | Новых доставок нет, статусы и даты запуска не сбрасываются |
| Падение до вызова оператора | Остановить процесс после захвата | После истечения срока и работы цикла восстановления доставка снова `Waiting`, затем обрабатывается; проверить предел 2 минуты на доступной БД |
| Падение после вызова оператора | Остановить процесс после успеха до сохранения результата | Повторный вызов возможен; отсутствие повторного внешнего эффекта текущий mock не доказывает |
| Явная ошибка оператора | Mock возвращает отказ | Доставка `Failed`, автоматического повтора нет; наличие ошибки не мешает завершению остальных доставок |
| Недоступность PostgreSQL | Отключить БД, затем восстановить | Уже сохранённые доставки остаются в БД, циклы повторяют работу; проверить восстановление закреплений и отдельный сбой перед завершением кампании |
| Согласованность счётчиков | Сверить после обработки с данными БД | Сумма `waiting + inProgress + sent + failed` равна `total`; у завершённой кампании нет незавершённых доставок |
| Пустая кампания | Создать и запустить без получателей | Зафиксировать ограничение: автоматической проверки завершения нет, кампания остаётся `InProgress` |
| Сбой формирования | Прервать создание между пакетами | При обработанном исключении сервис пытается удалить частичную кампанию; при аварии процесса автоматическая очистка не реализована |
| Сбой перед финальной проверкой | Прервать обработку после сохранения последнего результата | Зафиксировать ограничение: без отдельного обхода кампания может остаться `InProgress` |

# Критерий готовности

Для подтверждения целевых требований нужен воспроизводимый отчёт: параметры стенда, объём нагрузки, настройки воркеров и mock, задержки API, производительность, время завершения, итоговые счётчики и данные о смоделированных сбоях.

На теге `mvp` нельзя считать все требования выполненными: дедупликация оператором и восстановление завершения кампаний не реализованы, полнота журнала при сбоях не гарантируется, численные показатели требуют отдельного прогона. Эти ограничения зафиксированы без изменения кода.
