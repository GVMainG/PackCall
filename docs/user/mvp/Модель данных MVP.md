# Модель данных MVP

Срез реализации: тег `mvp`, коммит `f5dc35787b388466ae687493a5437f5f0c6e44a9` от 22.10.2026. Изменения после этого коммита в модель не включены.

Описание соответствует доменным сущностям и конфигурации Entity Framework на этом срезе. «Обязательность» означает запрет `NULL` в модели хранения, а не обязательность поля в запросе API. Даты хранятся в PostgreSQL как `timestamp with time zone`; приложение записывает время в UTC.

## Кампания

Таблица `campaigns`.

| Название поля | Поле в коде / столбец | Тип | Обязательность |
| --- | --- | --- | --- |
| Id | `Id` / `id` | GUID | Да |
| Название | `Name` / `name` | Строка до 255 символов | Да |
| Текст сообщения | `MessageText` / `message_text` | Текст | Да |
| Статус | `Status` / `status` | Целое число, статус кампании | Да |
| Дата создания | `CreatedAt` / `created_at` | Дата и время | Нет |
| Дата изменения | `UpdatedAt` / `updated_at` | Дата и время | Нет |
| Дата начала | `StartedAt` / `started_at` | Дата и время | Нет |
| Дата завершения | `CompletedAt` / `completed_at` | Дата и время | Нет |

Название и текст — non-null строки, поэтому EF Core делает столбцы обязательными по соглашению. При создании API заменяет отсутствующие значения пустыми строками; непустые название и текст проверяются при запуске и редактировании. Даты создания и изменения допускают `NULL` в модели, но сценарий создания их заполняет.

### Статусы кампании

| Значение в API | Значение в БД | Значение для пользователя |
| --- | --- | --- |
| `Draft` | 0 | Черновик, доступный для редактирования и запуска |
| `InProgress` | 1 | Запущена |
| `Completed` | 2 | Завершена |
| `Forming` | 3 | Формируется: создаются доставки |
| `Failed` | -1 | Ошибка; объявлен в перечислении, но рабочий сценарий MVP в него кампанию не переводит |

При создании кампания проходит `Draft` → `Forming` → `Draft`. Затем доступны переходы `Draft` → `InProgress` → `Completed`. Повторный запуск `InProgress` не меняет состояние и даты. Из `Completed` и `Failed` переходов нет. Пауза кампании на теге `mvp` отсутствует.

## Получатель

Таблица `recipients`.

| Название поля | Поле в коде / столбец | Тип | Обязательность |
| --- | --- | --- | --- |
| Id | `Id` / `id` | GUID | Да |
| Email | `Email` / `email` | Строка до 255 символов | Да |
| Дата создания | `CreatedAt` / `created_at` | Дата и время | Нет |
| Дата изменения | `UpdatedAt` / `updated_at` | Дата и время | Нет |

При добавлении через API email проверяется, обрезается по краям и приводится к нижнему регистру; даты заполняются текущим временем. В БД email уникален. Аудитория хранится в этой таблице и пополняется через API или подготовкой данных; внешняя CRM не подключена.

## Доставка

Таблица `deliveries`.

| Название поля | Поле в коде / столбец | Тип | Обязательность |
| --- | --- | --- | --- |
| Id | `Id` / `id` | GUID | Да |
| Кампания | `CampaignId` / `campaign_id` | GUID, ссылка на кампанию | Да |
| Получатель | `RecipientId` / `recipient_id` | GUID, ссылка на получателя | Да |
| Email получателя | `RecipientEmail` / `recipient_email` | Строка до 255 символов, снимок адреса | Да |
| Статус доставки | `DeliveryStatus` / `delivery_status` | Целое число, статус доставки | Да |
| Дата создания | `CreatedAt` / `created_at` | Дата и время | Да |
| Дата изменения | `UpdatedAt` / `updated_at` | Дата и время | Да |
| Дата завершения | `CompletedAt` / `completed_at` | Дата и время | Нет |
| Идентификатор воркера | `WorkerId` / `worker_id` | Строка до 255 символов | Нет |
| Срок закрепления | `LockExpiresAt` / `lock_expires_at` | Дата и время | Нет |

Email копируется из получателя при создании доставки. Текст сообщения отдельно в доставке не хранится: обработчик читает его из кампании, редактирование которой после запуска запрещено.

### Статусы доставки

| Значение в API | Значение в БД | Значение для пользователя |
| --- | --- | --- |
| `Waiting` | 0 | Ожидает |
| `InProgress` | 1 | Отправляется, закреплена за воркером |
| `Sent` | 2 | Отправлено: оператор подтвердил приём, доставка адресату неизвестна |
| `Failed` | -1 | Ошибка |

Допустимы переходы `Waiting` → `InProgress` → `Sent` или `Failed`, а также `InProgress` → `Waiting` после истечения закрепления. `Sent` и `Failed` — конечные статусы. При завершении заполняется `CompletedAt`, а `WorkerId` и `LockExpiresAt` очищаются; при возврате в ожидание очищаются только поля закрепления и обновляется `UpdatedAt`.

## Журнал смены статусов доставок

Таблица `delivery_status_journal`. Это инфраструктурная модель хранения, отдельная от доменных сущностей.

| Название поля | Поле в коде / столбец | Тип | Обязательность |
| --- | --- | --- | --- |
| Id записи | `Id` / `id` | 64-битное целое, генерируется БД | Да |
| Id кампании | `CampaignId` / `campaign_id` | GUID | Да |
| Id доставки | `DeliveryId` / `delivery_id` | GUID | Да |
| Прежний статус | `PreviousStatus` / `previous_status` | Статус доставки | Да |
| Новый статус | `NewStatus` / `new_status` | Статус доставки | Да |
| Идентификатор воркера | `WorkerId` / `worker_id` | Строка до 255 символов | Нет |
| Время события | `OccurredAt` / `occurred_at` | Дата и время | Да |
| Результат оператора | `OperatorResult` / `operator_result` | Строка до 1000 символов | Нет |

Сервис пишет журнал после захвата, сохранения конечного результата и возврата просроченного закрепления. Первичное создание доставки и статусы кампании в этом журнале не фиксируются. Успешный ответ обозначается `AcceptedByProvider`, ошибка — текстом оператора. При возврате просроченного закрепления `WorkerId` уже очищен, поэтому запись не содержит прежнего воркера. Изменение доставки и добавление записи выполняются раздельно: полнота журнала при сбое между этими действиями не гарантирована. HTTP-метода чтения журнала нет.

## Связи, уникальность и индексы

- Одна кампания содержит много доставок; один получатель может иметь доставки в разных кампаниях.
- Пара `CampaignId` + `RecipientId` уникальна: повторную доставку тому же получателю в той же кампании БД не допускает.
- Удаление кампании или получателя каскадно удаляет связанные доставки. API удаления получателя отсутствует.
- В журнале идентификаторы кампании и доставки хранятся без внешних ключей; каскадное удаление журнала не настроено.
- Для кампаний есть индексы по статусу и дате создания; для получателей — уникальный индекс по email.
- Для доставок есть индексы по паре кампания–получатель, статусу, паре статус–срок закрепления и дате создания.
- Для журнала есть индексы по парам кампания–время события и доставка–время события.
