# Структура проекта MVP

Срез реализации: тег `mvp`, коммит `f5dc35787b388466ae687493a5437f5f0c6e44a9` от 22.10.2026. Ниже описаны существующие проекты и подключения этого среза.

## PackCall.Core

Доменная модель, бизнес-правила и сценарии приложения. Не зависит от Entity Framework, PostgreSQL или ASP.NET Core.

Содержит:

- сущности `Campaign`, `Recipient`, `Delivery`, статусы и правила переходов;
- `CampaignService`: создание кампании с доставками, редактирование, запуск, удаление, создание и чтение получателей, чтение кампаний и доставок;
- `DeliveryProcessingService`: захват, обработка, возврат просроченных закреплений и проверка завершения кампании;
- интерфейсы сервисов, репозиториев, отправителя сообщений и журнала;
- модели страниц, счётчиков, запроса и результата отправки, записи смены статуса;
- доменные исключения и проверки инвариантов;
- интерфейсы метрик, вызовы которых в рабочем приложении обслуживаются пустой реализацией.

Отдельных команд и обработчиков в стиле CQRS нет: API вызывает методы сервисов. Внешние зависимости реализуются через интерфейсы Core; названия и смысл основных моделей описаны в [модели данных](Модель%20данных%20MVP.md).

## PackCall.Infrastructure

Технические реализации интерфейсов Core. Зависит от Core.

Содержит:

- `AppDbContext` с конфигурацией таблиц, связей и индексов для PostgreSQL через EF Core;
- репозитории кампаний, получателей и доставок;
- атомарный захват доставок через PostgreSQL `FOR UPDATE SKIP LOCKED`, сохранение воркера и срока закрепления;
- пакетную запись доставок через отдельный контекст для каждого пакета;
- `MockEmailSender`, имитирующий ответ оператора;
- хранение журнала смены статусов в `delivery_status_journal`;
- `ServiceCollectionExtensions.AddInfrastructure` для регистрации зависимостей;
- классы метрик и чтения состояния, которые на этом срезе не подключены; вместо сбора метрик зарегистрирован `NoOpDeliveryMetrics`.

EF-миграций на теге `mvp` нет. Приложение создаёт схему через `EnsureCreatedAsync`; это не механизм обновления уже существующей схемы.

## PackCall.Api

HTTP-интерфейс и фоновая обработка в одном процессе. Зависит напрямую от Core и Infrastructure.

Содержит:

- контроллеры кампаний, доставок и получателей;
- HTTP-модели запросов и ответов, преобразование моделей;
- обработчик ошибок с `ProblemDetails`;
- OpenAPI и Swagger UI, доступные только в `Development`;
- Serilog, регистрацию сервисов и настройку PostgreSQL;
- `DeliveryWorker` как `BackgroundService`, отдельные циклы обработки и восстановления закреплений;
- `DeliveryWorkerOptions`: по умолчанию четыре параллельных цикла и пакет до десяти доставок на цикл.

Контроллеры и воркер вызывают сервисы Core. При старте приложения код `Program` создаёт контекст для `EnsureCreatedAsync`. Отдельного запускаемого проекта воркера нет. Класс `MetricsController` существует, но помечен `NonController`: маршрут `/metrics` отключён.

## PackCall.Core.Test

Проект тестов на xUnit для .NET 10. Проверяет доменные переходы, сервисы, API-контроллеры, фоновый обработчик и сценарии через тестовые зависимости. Наличие этих тестов само по себе не подтверждает нагрузочные цели и корректность конкурентных SQL-операций на реальном PostgreSQL.

## Остальные файлы

- `PackCall.slnx` — решение.
- `docker-compose.yml` — API и PostgreSQL с постоянным томом; `docker-compose.override.yml` — настройки разработки.
- `src/PackCall.Api/Dockerfile` — сборка образа API.
- `src/PackCall.Api/PackCall.Api.http` — примеры HTTP-запросов.
- `scripts/load-test/seed_100000_recipients.sql` — подготовка 100 000 получателей для нагрузочного сценария; это не отчёт о результатах прогона.
