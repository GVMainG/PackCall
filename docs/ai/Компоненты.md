# Компоненты

Компонентом здесь считается класс или группа тесно связанных классов с самостоятельной ответственностью. Отдельная запись нужна, когда назначение, готовность и подключение части системы можно оценить независимо. Простые DTO и вспомогательные типы не перечисляются отдельно. Правила поведения находятся в [Правилах домена](./Правила%20домена.md), связи между частями — в [Контрактах между компонентами](./Контракты%20между%20компонентами.md).

## Как читать статусы

- **В плане** — компонент внесён в план владельцем проекта; из отсутствия кода планы не выводятся.
- **В разработке** — есть код или контракт, но заявленная ответственность ещё не обеспечена полностью.
- **Реализован** — заявленная ответственность выполняется в коде компонента. Это не означает подтверждения нагрузочных и аварийных гарантий.
- **Подключён** — в коде приложения есть путь выполнения до компонента. Ссылка на проект или регистрация без вызова недостаточна. Здесь оценено подключение по исходникам, а не результат отдельного запуска приложения.

Секция `DeliveryWorker` задаёт `Parallelism: 4`, `BatchSize: 10`; изменения применяются после перезапуска. |

Получателей можно создавать через API; отдельный [SQL-скрипт](../../scripts/load-test/seed_100000_recipients.sql) наполняет базу нагрузочными данными. Автоматического начального заполнения нет, поэтому на пустой базе создание кампании не создаёт доставок. Запущенная пустая кампания остаётся в `InProgress` до явной проверки завершения или операции возобновления. Приостановленная кампания не завершается автоматически до возобновления.

Реализации и подключения перечислены по текущим исходникам. Помимо тестов с подставными зависимостями, [CampaignPausePostgresTests](../../PackCall.Core.Test/CampaignPausePostgresTests.cs) содержит проверки паузы, конкурентной смены статусов, освобождения закреплений и HTTP на PostgreSQL в отдельных временных схемах. Они требуют `PACKCALL_TEST_POSTGRES` и без этой переменной пропускаются. Эти сценарии не подтверждают нагрузочные показатели и подавление дублей при аварии отправки. Планируемые компоненты и их назначение добавляет владелец проекта; отсутствие класса само по себе не создаёт новую запись «В плане».
