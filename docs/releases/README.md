# Заметки о релизах и runbook

Заметки о релизе — `docs/releases/<tag>.md`, по файлу на тег, имя файла — полное имя тега
(`v0.5.0-beta.2.md`): что вошло, что не вошло, известные ограничения и исправления предыдущего
релиза. В заметках указывается commit SHA тега; SHA в заметках обязан совпадать с SHA тега
(расхождение — блокер тега, см. [`../EVIDENCE.md`](../EVIDENCE.md)). Для исторических `mvp`/`v0.5.0-beta.1`
заметки не пересоздаются (FR-21).

## Runbook тега (DoD, roadmap §9)

1. **CI зелёный** — обязательный check `CI required` прошёл для целевого коммита;
   `python3 scripts/ci/release_gate.py --commit <sha>` → exit 0 (см. [`../../README.md`](../../README.md)).
2. **Evidence с SHA** — результаты и их команды в `docs/evidence/<tag>/`, каждый артефакт содержит
   commit SHA и версию окружения (правила — [`../EVIDENCE.md`](../EVIDENCE.md)).
3. **Release notes** — `docs/releases/<tag>.md` с «что вошло / не вошло / ограничения /
   исправления», SHA равен SHA тега.
4. **Annotated-тег** — `git tag -a <tag> -m "..." <sha>` на том же коммите.
5. **SHA совпадает** — SHA в release notes = `git rev-parse <tag>^{commit}`; расхождение — блокер.
6. **Тег не переносится и не удаляется** — дефект после тега исправляется следующим релизом;
   исключение — компрометация секрета.
7. **Теги не переименовываются и не переносятся.** Исключение — компрометация секрета или чистка
   истории по решению владельца.

Порядок фиксированный; шаг 1 (зелёный CI) выполняется до тега. **FAIL-RECORDED** — провал,
записанный с причиной и решением владельца; он блокирует тег, релиз остаётся открытым.
