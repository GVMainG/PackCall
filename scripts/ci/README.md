# CI-проверки исходников

## `check_utf8_sources.py`

Строгая проверка кодировки исходников C#: каждый git-tracked `*.cs` (расширение сравнивается
без учёта регистра) обязан декодироваться как UTF-8 без замены и не содержать U+FFFD — признак
того, что текст где-то был декодирован с потерей.

Команды:

- `python3 scripts/ci/check_utf8_sources.py` — проверить все tracked `*.cs`;
- `python3 scripts/ci/check_utf8_sources.py --paths FILE...` — проверить указанные файлы
  (используется тестами гейта).

Коды выхода: `0` — всё валидно, `1` — найден невалидный файл, `2` — ошибка окружения
(нет git, не git-репозиторий, файл не читается).

Ограничения контракта:

- BOM в начале файла допускается: это валидный UTF-8, он не скрывает текст;
- для файла сообщается только первое невалидное смещение; смещение — в байтах файла на диске,
  номер строки считается для LF, CRLF и CR;
- проверяется кодировка и целостность текста. Смысловая корректность текста (валидный UTF-8
  с неверными символами, но без U+FFFD) — вне контракта гейта.

## `check_trx.py`

Защита unit-job от «пустого» прогона: читает TRX и падает, если в отчёте нет ни одного
исполненного теста (сломанный фильтр или переименованный trait не должны превращать гейт в no-op).

- `python3 scripts/ci/check_trx.py artifacts/test-results/unit.trx`
- Коды выхода: `0` — тесты исполнены (печатается число), `1` — ноль тестов, `2` — TRX
  не читается/невалиден.

## `release_gate.py`

Проверка перед постановкой тега: для указанного коммита через GitHub API проверяется, что
обязательный агрегирующий check (`CI required`) последнего запуска завершён успешно и опубликован
GitHub Actions.

Команда:

```bash
GITHUB_TOKEN=... python3 scripts/ci/release_gate.py --commit <40-hex-sha>
```

Параметры: `--commit` (обязательный, полный 40-hex SHA), `--repo owner/name` (по умолчанию
`GITHUB_REPOSITORY`), `--required NAME` (повторяемый; по умолчанию `CI required`).

Коды выхода: `0` — все обязательные проверки успешны, `1` — проверка провалена, отсутствует,
опубликована не GitHub Actions или ещё выполняется (тег не ставится; также 404/422), `2` — ошибка
окружения: нет токена/репозитория, 401/403/5xx, сеть, некорректный JSON или форма ответа.

Ограничения контракта:

- запрос идёт по одному имени check (`check_name=<name>&filter=latest`), поэтому пагинация
  страницы не влияет на результат; авторитетен последний запуск по имени;
- принимаются только check-runs с `app.slug = github-actions`;
- поддерживается только `github.com` (GHES не поддержан), без retry/backoff: транзиентные
  ошибки возвращают exit 2 и требуют повторного запуска.

Токен читается только из `GITHUB_TOKEN` и никогда не печатается.

## Тесты

Все офлайн-проверки — `tests/tools/ci`:

```bash
python -m unittest discover -s tests/tools/ci -p "test_*.py" -v
```

В CI они запускаются в job `utf8_sources` («Strict UTF-8 sources», `.github/workflows/ci.yml`)
перед самой проверкой исходников; структурный тест workflow проверяет, что имя агрегирующего
check совпадает с умолчанием гейта, а все job перечислены в `ci_required.needs`.
