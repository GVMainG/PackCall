# Proposal

## Why

Тестовая база смешивает проверки с фейками, PostgreSQL, HTTP и файловым выводом в одном проекте; пять файлов образуют один PostgreSQL partial-класс, а Docker-runner повторяют подготовку и проверки. Это усложняет сопровождение и позволяет принять неполный прогон за успешный; сокращения должны опираться на поведение и оставшиеся assertions, без целевого процента.

## What Changes

- Перенести C#-сценарии в `tests/PackCall.UnitTests` и `tests/PackCall.IntegrationTests`, разложить по модулям и разделить `CampaignPausePostgresTests` на независимые классы. Сначала сохранить все сценарии и строки theory.
- Выделить общую PostgreSQL-фикстуру: один Docker PostgreSQL на интеграционный прогон, собственная мигрированная схема каждого теста, независимые контексты и соединения гонок. Для SchemaGate оставить отдельную подготовку истории.
- Объединить ограниченную по времени Python Docker/SQL/HTTP-обвязку, build/publish и проверку результатов в небольших функциях; закрепить обязательный запуск integration без skipped и владение ресурсами конкретного прогона.
- После переноса выполнить только доказанные сокращения по реестру design: пауза последней отправки, recovery на фейке, фрагмент API-теста, лишняя ось simulate в PostgreSQL-матрице, shutdown-runner и retention. Отличающиеся проверки сначала перенести/усилить; при отсутствии эквивалента исходный тест оставить.
- Уточнить проверки `SendResult`, доменных переходов Delivery, реальной компенсации формирования и обработки доставки при сбоях telemetry callback/файлового writer. Не смешивать телеметрию с бизнес-журналом.
- Восстановить повреждённые сообщения `DeliveryWorker.cs` вместе с устранением текстовой синхронизации `late_http.py`; перевести содержательные комментарии, поясняя причины и ограничения.
- Сохранить Docker, xUnit 2, весь стенд измерений, W22 и реальные компоненты. Testcontainers, новая библиотека TestUtilities, новый тестовый фреймворк и новые тесты результатов измерений не входят в change.

## Capabilities

### New Capabilities

- `test-suite-execution`: воспроизводимый раздельный запуск unit/integration/acceptance, изоляция ресурсов, проверка полноты и доказуемое сохранение критичных сценариев при сокращении. Это контракт инструментария разработчика: integration без БД должен завершаться ошибкой вместо нынешнего пропуска PostgreSQL-тестов.

### Modified Capabilities

Нет. Требования бизнес-поведения и `runtime-performance-measurement` сохраняются; уточнение их проверок не меняет контракт приложения.

## Impact

Будущая реализация затронет `PackCall.Core.Test/**`, `PackCall.slnx`, новые `tests/PackCall.{UnitTests,IntegrationTests}/**`, `tests/support/**`, `tests/acceptance/**`, launchers `scripts/performance/postgres_tests.py` и повторную публикацию в `crash_smoke.py`, документацию команд. В `src/**` допускаются только согласованные пояснения и исправление повреждённых сообщений; generated-файлы ради комментариев не менять. Стенд `scripts/performance` сохраняет форматы, алгоритмы, SQL и действующие проверки. API, схема production-БД, зависимости и семантика обработки не меняются.

В этой сессии создаются только planning-артефакты. Проверка исходников статическая: тесты, Docker и миграции не запускались. Подробные подтверждения, корректировки аудита, пути, риски и этапные критерии находятся в `design.md` и `tasks.md`.
